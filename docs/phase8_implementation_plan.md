# Phase 8 Implementation Plan — NLP/IR Evaluation, Benchmark Dataset & Performance Validation

## 1. Evaluation Objective
The objective of Phase 8 is to transform the ASTMA Evaluation workspace from a methodology placeholder into an empirical, reproducible Information Retrieval (IR) and Natural Language Processing (NLP) evaluation engine. This will quantitatively measure the extraction accuracy (Precision, Recall, F1-score) of both the Keyword Extraction Pipeline (RAKE, TF-IDF, Lexicon) and the Named Entity Recognition (NER) pipeline (spaCy, Regex, Legal Gazetteers) against a curated legal ground-truth benchmark dataset.

---

## 4. Keyword Evaluation Methodology
- **Target Comparison:** Compare predicted keywords (top $K \in \{5, 10, 20\}$ and unconstrained) against gold keywords.
- **Top-K Evaluation:**
  - Precision@5, Precision@10, Precision@20
  - Recall@5, Recall@10, Recall@20
  - F1@5, F1@10, F1@20
- **Ablation Comparison:** Where practical, evaluate the candidate scores generated by:
  - TF-IDF Alone
  - RAKE Alone
  - Full Hybrid Fusion (TF-IDF + RAKE + Lexicon)

---

## 5. Entity Evaluation Methodology
- **Target Comparison:** Compare extracted entities against gold entities.
- **Criteria for Match:**
  - Normalized text match (case-folded, whitespace-standardized).
  - Exact category/entity-type agreement (`pred_type == gold_type`).
  - No cross-category aliasing (e.g. `COURT` vs `ORGANIZATION` counts as a type mismatch).

---

## 6. Metric Calculations
All formulas handle zero denominators safely ($0/0 \rightarrow 0.0$):

$$\text{Precision} = \frac{TP}{TP + FP}$$

$$\text{Recall} = \frac{TP}{TP + FN}$$

$$F_1 = \begin{cases} 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}} & \text{if } \text{Precision} + \text{Recall} > 0 \\ 0.0 & \text{otherwise} \end{cases}$$

- **Macro Average:** Arithmetic mean across all evaluated documents:
  $$\text{Macro } F_1 = \frac{1}{N} \sum_{i=1}^N F_{1, i}$$
- **Micro Average:** Global pooling of counts across all documents:
  $$\text{Micro Precision} = \frac{\sum TP_i}{\sum TP_i + \sum FP_i}$$

---

## 7. Matching Strategy & Text Normalization
1. **Case Normalization:** String lowercasing (`"Section 11"` $\rightarrow$ `"section 11"`).
2. **Whitespace Canonicalization:** Strip leading/trailing whitespaces and collapse multi-space/tab sequences to a single space.
3. **Punctuation Trimming:** Strip leading/trailing punctuation characters (quotes, commas, periods) from tokens.
4. **Sub-string / Boundary Matching:** Exact token match post-normalization. Deterministic, without artificial vector embedding fuzziness.

---

## 8. Error Classification
For each evaluated document, partition predictions and gold standard into:
1. **True Positives ($TP$):** Predicted item correctly present in gold annotations.
2. **False Positives ($FP$):** Predicted item not in gold annotations (spurious extraction).
3. **False Negatives ($FN$):** Gold item omitted by the extraction pipeline (missed recall).
4. **Entity Type Mismatches:** Correct text boundary detected, but assigned incorrect semantic type (e.g., predicted `ORGANIZATION` when gold is `COURT`).

---

## 9. Performance Measurement
Measure actual wall-clock timing using Python `time.perf_counter()`:
- `text_extraction_ms`
- `keyword_extraction_ms`
- `entity_extraction_ms`
- `total_processing_ms`
Compute Average, Minimum, and Maximum runtimes across the corpus.

## 10. Evaluation API Architecture
Dedicated API endpoints in `backend/app/api/v1/endpoints/evaluation.py`:
- `GET /api/v1/evaluation/summary`: Return latest evaluation run summary and metrics.
- `GET /api/v1/evaluation/documents`: Return per-document breakdown.
- `GET /api/v1/evaluation/documents/{document_id}`: Return detailed analysis and error breakdown for a single document.
- `POST /api/v1/evaluation/run`: Trigger live execution of the benchmark evaluation suite. Protected by RBAC (Analyst or Admin only).

---

## 11. Evaluation UI Architecture (`EvaluationPage.jsx`)
Upgrade the existing methodology view to an interactive evaluation suite:
1. **Action Bar:** "Run Benchmark Evaluation" button with real indeterminate progress loader and timestamp of last execution.
2. **Scorecard Grid:** Precision, Recall, and F1 metric cards with educational definitions and mathematical formulas.
3. **Performance Metrics Panel:** Average, Min, Max processing latencies and total document count.
4. **Ablation Comparison Table:** Keyword model comparison (TF-IDF vs RAKE vs Hybrid).
5. **Document-Level Results Table:** Sortable per-document metrics with click-to-expand.
6. **Error Analysis Inspector:** Dedicated tabs for False Positive Keywords, False Negative Keywords, and Entity Classification Errors.

4. Partial match scenario.
5. Case and whitespace normalization invariance.
6. Entity type mismatch handling.
7. Top-K cutoff truncation.
8. Benchmark corpus file loader validation.
9. Evaluation API endpoint authentication and RBAC gating.
